# Internationalization (i18n)

The `@barqel/barq-i18n` plugin adds localized API responses, RFC `Accept-Language` quality weight negotiation, and string interpolation to Barq without external dependencies.

## Installation

```bash
bun add @barqel/barq-i18n
```

## Quick Start

```ts
import { App, json } from "@barqel/barq";
import { i18nPlugin } from "@barqel/barq-i18n";

const app = new App();

app.plugin(
  i18nPlugin({
    defaultLocale: "en",
    locales: ["en", "ar", "fr"],
    translations: {
      en: {
        welcome: "Welcome, {name}!",
        errors: { notFound: "Item not found" },
      },
      ar: {
        welcome: "مرحباً، {name}!",
        errors: { notFound: "العنصر غير موجود" },
      },
    },
  })
);

app.get("/hello", (ctx) => {
  const t = (ctx as any).t;
  return json({
    locale: ctx.state.locale,
    message: t("welcome", { name: "Ada" }),
    error: t("errors.notFound"),
  });
});

app.listen(3000);
```

## Locale Resolution Hierarchy

Locales are determined in the following order:
1. Custom extractor function (if provided)
2. URL Query parameter (`?lang=ar`)
3. Cookies (`lang=ar`)
4. `Accept-Language` HTTP header (with q-factor weights)
5. Default fallback locale
