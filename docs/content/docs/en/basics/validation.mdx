Before processing any request on your server, ensuring incoming input conforms to expected rules is vital for application stability and security.

The HTTP validation APIs in these examples work on Bun and Node.js, and the same `@barqel/barq` import covers both. The upload example uses `Bun.write()` to save a file; replace it with Node.js filesystem APIs when using the Node adapter. Node.js deployments must enforce request-size limits at the HTTP server or reverse proxy because `maxRequestBodySize` is Bun-specific.

Barq supports two primary validation patterns:
1. Using the built-in `validateJson` helper compliant with the **Standard Schema v1** specification (such as Zod).
2. Direct inline validation inside route handlers (**without `validateJson`**) for all payload types (JSON, Query parameters, FormData, and File uploads).

## 1. Using Zod with the Built-in `validateJson` Helper

Zod supports the **Standard Schema v1** specification out of the box. When passing a schema to `validateJson`, Barq automatically reads the request body, executes validation, and returns a `422 Unprocessable Entity` response containing an `issues` array if validation fails.

### Complete Example: User Registration

```ts
import { App, json, validateJson } from "@barqel/barq";
import { z } from "zod";

// 1. Define the schema
const CreateUserSchema = z.object({
  name: z.string().min(2, "Name must be at least 2 characters"),
  email: z.string().email("Invalid email address"),
  age: z.number().int().positive("Age must be a positive integer"),
  role: z.enum(["user", "admin"]).default("user"),
});

const app = new App();

// 2. Register route with validateJson
app.post(
  "/users",
  validateJson(CreateUserSchema, (ctx, body) => {
    // body is verified and fully typed according to the schema:
    // body: { name: string; email: string; age: number; role: "user" | "admin" }
    return json(
      {
        message: "User created successfully",
        user: {
          name: body.name,
          email: body.email,
          age: body.age,
          role: body.role,
        },
      },
      201,
    );
  }),
);

app.listen(3000);
```

#### Automated Error Response on Failure (422):
```json
{
  "error": "Validation Failed",
  "issues": [
    {
      "message": "Age must be a positive integer",
      "path": ["age"]
    }
  ]
}
```

## 2. Direct JSON Validation inside Handlers (Without `validateJson`)

If you prefer custom error formats or want to avoid higher-order wrapper functions, invoke `schema.safeParse` directly inside your route handler:

### Complete Example: Login Handler with Inline Zod Validation

```ts
import { App, json, HttpError } from "@barqel/barq";
import { z } from "zod";

const LoginSchema = z.object({
  username: z.string().min(3, "Username must be at least 3 characters"),
  password: z.string().min(8, "Password must be at least 8 characters"),
});

const app = new App();

app.post("/login", async (ctx) => {
  // 1. Manually parse JSON from the request context
  const rawBody = await ctx.json<unknown>();

  // 2. Validate using safeParse
  const result = LoginSchema.safeParse(rawBody);

  // 3. Handle validation errors with custom HttpError
  if (!result.success) {
    throw new HttpError(422, {
      error: "Invalid credentials payload",
      details: result.error.flatten().fieldErrors,
    });
  }

  // 4. Safely access typed data
  const { username, password } = result.data;

  // Execute authentication logic...
  return json({
    success: true,
    user: username,
  });
});

app.listen(3000);
```

## 3. Validating Query and Route Parameters

Query and URL parameters are always received as strings. Use Zod's **`z.coerce`** to automatically convert strings to numbers, booleans, or dates:

### Complete Example: Search & Pagination Filter

```ts
import { App, json, HttpError } from "@barqel/barq";
import { z } from "zod";

const QueryFilterSchema = z.object({
  q: z.string().min(1, "Search keyword is required"),
  // z.coerce.number transforms the string "2" into the integer 2
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(10),
  sort: z.enum(["price_asc", "price_desc", "newest"]).default("newest"),
});

const app = new App();

app.get("/products", (ctx) => {
  // Gather query parameters into a plain object
  const rawParams = {
    q: ctx.queryParam("q"),
    page: ctx.queryParam("page"),
    limit: ctx.queryParam("limit"),
    sort: ctx.queryParam("sort"),
  };

  const validation = QueryFilterSchema.safeParse(rawParams);

  if (!validation.success) {
    throw new HttpError(400, {
      error: "Invalid query parameters",
      details: validation.error.flatten().fieldErrors,
    });
  }

  // Fully coerced and validated fields
  const { q, page, limit, sort } = validation.data;

  return json({
    query: q,
    page,
    limit,
    sort,
    items: [],
  });
});

app.listen(3000);
```

## 4. Validating Forms and File Uploads (`FormData & Files`)

To validate multipart form payloads and uploaded files, use standard `File` checks combined with `z.instanceof(File)` to inspect file types and file sizes:

### Complete Example: Profile Image Upload with Constraints

```ts
import { App, json, HttpError } from "@barqel/barq";
import { z } from "zod";

const MAX_FILE_SIZE = 2 * 1024 * 1024; // 2MB
const ACCEPTED_IMAGE_TYPES = ["image/jpeg", "image/png", "image/webp"];

const ProfileUploadSchema = z.object({
  title: z.string().min(2, "Title must be at least 2 characters"),
  avatar: z
    .instanceof(File, { message: "Avatar file is required" })
    .refine((file) => file.size <= MAX_FILE_SIZE, "File size must not exceed 2MB")
    .refine(
      (file) => ACCEPTED_IMAGE_TYPES.includes(file.type),
      "Only JPG, PNG, and WEBP formats are allowed",
    ),
});

const app = new App({
  // Configure server-wide max request body limit
  maxRequestBodySize: 10 * 1024 * 1024,
});

app.post("/profile/upload", async (ctx) => {
  // 1. Read FormData from context
  const form = await ctx.formData();

  // 2. Extract form fields
  const rawData = {
    title: form.get("title"),
    avatar: form.get("avatar"),
  };

  // 3. Validate with Zod
  const result = ProfileUploadSchema.safeParse(rawData);

  if (!result.success) {
    throw new HttpError(422, {
      error: "Validation failed for uploaded payload",
      issues: result.error.flatten().fieldErrors,
    });
  }

  const { title, avatar } = result.data;

  // 4. Save file to disk using Bun's native write
  const fileName = `${Date.now()}-${avatar.name}`;
  await Bun.write(`./uploads/${fileName}`, avatar);

  return json(
    {
      success: true,
      title,
      savedFile: fileName,
      fileSize: avatar.size,
    },
    201,
  );
});

app.listen(3000);
```

## 5. Pure Zero-Dependency Validation (No External Libraries)

If you prefer to avoid third-party dependencies completely and validate with pure JavaScript/TypeScript:

### Complete Example: Pure Manual Validator

```ts
import { App, json, HttpError } from "@barqel/barq";

const app = new App();

app.post("/pure-check", async (ctx) => {
  const data = await ctx.json<unknown>();

  if (typeof data !== "object" || data === null || Array.isArray(data)) {
    throw new HttpError(400, { error: "Valid JSON object required" });
  }

  const payload = data as Record<string, unknown>;

  // Validate name
  if (typeof payload.name !== "string" || payload.name.trim().length < 2) {
    throw new HttpError(422, { error: "Field 'name' must be at least 2 characters" });
  }

  // Validate email
  if (
    typeof payload.email !== "string" ||
    !payload.email.includes("@") ||
    !payload.email.includes(".")
  ) {
    throw new HttpError(422, { error: "Invalid email address format" });
  }

  return json({
    verified: true,
    user: {
      name: payload.name.trim(),
      email: payload.email.trim(),
    },
  });
});

app.listen(3000);
```

## Summary Comparison

| Pattern | Tool | Recommended Use Case | Benefits |
|---|---|---|---|
| **`validateJson`** | Standard Schema / Zod | Standard REST API endpoints | Less code, automatic type inference, built-in 422 error |
| **Inline Schema Validation** | `Schema.safeParse` in handler | Forms, file uploads, query filters | Complete control over errors and file streams |
| **Pure Manual Validation** | Native TypeScript guards | Critical high-performance routes | Zero dependencies, lowest overhead, zero intermediary allocations |
