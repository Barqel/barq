# Installation

Get started with **Barq** in just a few minutes. Choose Bun or Node.js for HTTP, install the package, and create a JavaScript entry file.

This guide walks you through the process, from checking the requirements to running your server locally.

## Requirements

Before installing Barq, make sure you have the following:

- **Node.js 18 or later** for HTTP applications, or **[Bun](https://bun.sh/) 1.1 or later**. Barq's Node.js adapter supports HTTP; native WebSockets and Bun-specific server options require Bun.
- **JavaScript or TypeScript.** The examples below use JavaScript so they run directly with `node`. Bun can also run TypeScript files without a separate compilation step. To run TypeScript on Node.js, compile it to JavaScript first, then run the output with `node`.

Check the runtime you plan to use:

```sh
node --version
bun --version
```

Install Node.js from [nodejs.org](https://nodejs.org/) or Bun from the [official Bun website](https://bun.sh/).

## Install Barq

The fastest way to get started is to create a new directory, initialize it, and install the latest version of the package all at once:

<Tabs syncKey="package-manager">
<TabItem label="Bun">

```sh
mkdir app-barq && cd app-barq
bun init -y
bun add @barqel/barq@latest
```

</TabItem>
<TabItem label="npm">

```sh
mkdir app-barq && cd app-barq
npm init -y
npm install @barqel/barq@latest
```

</TabItem>
</Tabs>

This command adds the `@barqel/barq` package to your project's dependencies.
For an existing project, install it with `npm install @barqel/barq` or `bun add @barqel/barq`.

## Import Barq

Barq is an ECMAScript Module (ESM) package, and a single import covers both runtimes. The package root resolves to whichever HTTP server you actually run — Bun's native server under Bun, and the Node.js adapter under Node.js:

```js
import { App, json } from "@barqel/barq";
```

The rest of the HTTP API is the same in both runtimes. WebSocket routes, TLS server options, worker clustering, and Bun-specific server limits require Bun; see [Server Configuration](/en/docs/runtime/server) and [WebSocket Connections](/en/docs/runtime/websockets).

Barq has no required runtime package dependencies. npm and Bun are both supported package managers; the runtime you choose determines which server features are available.

## Create an entry point

An entry point is the file where your application starts executing. For a JavaScript application, create this file:

```text
src/
└── index.js
```

Add the server code you want to run to this file. If you use npm and Node.js, enable ESM in your project:

```sh
npm pkg set type=module
```

Follow the [Quickstart](/en/docs/getting-started/quickstart) for a complete example. Start the same JavaScript entry point with the runtime of your choice:

<Tabs syncKey="runtime">
<TabItem label="Node.js">

```sh
node src/index.js
```

</TabItem>
<TabItem label="Bun">

```sh
bun run src/index.js
```

</TabItem>
</Tabs>

Node.js runs JavaScript directly; this guide does not require `tsx` or a TypeScript runtime loader. If your server listens on a specific port, send requests to its local address and configured port.

## Configure the server port

A port determines where your server accepts HTTP connections. For example, a server listening on port `3000` is commonly accessed locally at:

```text
http://localhost:3000
```

If you do not specify a port in `listen()` or `AppOptions.port`, Bun may select an available port automatically. For a predictable local address, configure the port explicitly or read it from the `PORT` environment variable.

For a local service, you can explicitly configure the port or read it from the `PORT` environment variable, with `3000` as the default:

```js
const port = Number(process.env.PORT ?? 3000);
```

Here is how the expression works:

1. It reads `process.env.PORT` if the `PORT` environment variable is defined.
2. It falls back to `3000` if the variable is missing.
3. It converts the resulting value to a number using `Number()`.

This expression only prepares the port value. Pass it to `new App({ port })` or `app.listen(port)`, and verify that `PORT` contains a valid number and that the selected port is available. `process.env` works in both Node.js and Bun.
