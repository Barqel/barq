## From request to response. With less overhead.

Your framework should not spend time doing work your application doesn't need. **Barq** provides a fast, lightweight foundation for HTTP services and APIs on **Bun and Node.js**. Native WebSocket support currently requires Bun.

Barq uses Bun's native server or its Node.js HTTP adapter, with a Trie-based router to match routes efficiently and reduce unnecessary work along the request path.

**The goal: high performance, clear code, and more freedom to build your application your way.**

## A simple start. Real results.

Create an application, register a route, and return a JSON response. That's all you need to understand the basics:

```js
import { App, json } from "@barqel/barq";

const app = new App();

app.get("/users/:id", (ctx) => {
  return json({ id: ctx.params.id });
});

const server = app.listen(3000);

console.log(`Server running at http://localhost:${server.port}`);
```

Run the application and send a request to:

`http://localhost:3000/users/42`

The expected response is:

```json
{
  "id": "42"
}
```

Here's what happens:

- `App` creates a Barq application.
- `app.get()` registers a handler for `GET` requests to the specified route.
- `ctx.params.id` reads the `id` value from the request URL.
- `json()` returns the data as JSON.
- `app.listen(3000)` starts the server on port `3000`.

This example runs on both runtimes: the `@barqel/barq` import resolves to the Node.js HTTP adapter or to Bun's native server. The route code is unchanged.

You don't need a large setup to get started. Begin with one route, then add the rest of your application's features step by step.

## Every millisecond matters.

Speed isn't an afterthought in Barq's design. It's one of the core goals.

Barq focuses on Bun's native server, its Node.js HTTP adapter, Trie-based routing, and reducing unnecessary work along the request path. The aim is fast execution without adding needless complexity to your code.

Real-world performance also depends on what your application does, response sizes, workload, and runtime environment. That's why Barq should be evaluated with repeatable benchmarks that compare equivalent scenarios and report results clearly.
