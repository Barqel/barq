يحدد **التوجيه (Routing)** كيفية استقبال التطبيق لطلبات HTTP والتعامل معها. عندما يرسل العميل طلبًا إلى مسار مثل `/users/42`، يحدد Barq المعالج المناسب بناءً على المسار وطريقة HTTP، ثم يمرر إليه بيانات الطلب ليعيد الاستجابة المطلوبة.

يوفر Barq واجهة مباشرة لتسجيل المسارات، مع دعم معاملات المسار، ومعاملات الاستعلام، والمجموعات، والإضافات، من دون الحاجة إلى كتابة نظام توجيه يدوي.

## طرق HTTP

لكل طريقة HTTP دالة مقابلة في Barq. اختر الطريقة التي تعبّر عن العملية التي ينفذها المسار.

| الطريقة | الاستخدام المعتاد |
|---|---|
| `get()` | قراءة البيانات أو جلب مورد. |
| `post()` | إنشاء مورد أو تنفيذ عملية. |
| `put()` | استبدال مورد أو تحديثه بالكامل وفقًا لقواعد التطبيق. |
| `patch()` | تحديث جزء من مورد. |
| `delete()` | حذف مورد. |
| `head()` | طلب ترويسات الاستجابة من دون محتواها. |
| `options()` | معرفة الطرق أو الخيارات المتاحة للمسار. |
| `all()` | تسجيل معالج لجميع طرق HTTP التي يدعمها Barq. |

### مثال عملي

```ts
import { App, json } from "@barqel/barq";

const app = new App();

app.get("/health", () => json({ ok: true }));

app.post("/users", createUser);
app.put("/users/:id", replaceUser);
app.patch("/users/:id", updateUser);
app.delete("/users/:id", deleteUser);

app.head("/health", healthHead);
app.options("/users", usersOptions);
```

في هذا المثال، يفصل التطبيق بين العمليات بحسب طريقة الطلب:

- `GET /health` يعيد حالة التطبيق.
- `POST /users` ينفذ منطق إنشاء مستخدم.
- `PUT /users/:id` يستدعي معالج استبدال المستخدم.
- `PATCH /users/:id` يستدعي معالج تحديث المستخدم.
- `DELETE /users/:id` يستدعي معالج حذف المستخدم.

الدوال `createUser` و`replaceUser` وغيرها في المثال معالجات يفترض أن تعرّفها في تطبيقك؛ فهي ليست دوالًا يوفرها Barq تلقائيًا.

### تسجيل معالج لجميع الطرق

إذا أردت أن يستقبل مسار معين الطلبات عبر جميع طرق HTTP التي يدعمها Barq، فاستخدم `all()`:

```ts
app.all("/webhook", handleWebhook);
```

يكون ذلك مفيدًا عندما تحتاج إلى معالجة الطلبات بطرق مختلفة داخل معالج واحد، مثل بعض نقاط استقبال الإشعارات الخارجية. ومع ذلك، فضّل تسجيل الطريقة المحددة عندما تكون العملية مرتبطة بطريقة واحدة؛ فهذا يجعل واجهة التطبيق أوضح.

### إضافة الوسائط قبل المعالج

تقبل دوال تسجيل المسارات صفرًا أو أكثر من دوال الوسائط البرمجية (`middleware`) قبل المعالج النهائي.

```ts
app.get(
  "/account",
  requireAuthentication,
  loadAccount,
  (ctx) => json({ account: ctx.state.account }),
);
```

في هذا المثال، تُسجَّل وسائط المصادقة وتحميل الحساب قبل المعالج النهائي. ويعتمد التنفيذ الفعلي على طريقة عمل هذه الوسائط في تطبيقك: يجب أن تسمح الوسائط باستمرار الطلب حتى يصل إلى المعالج النهائي، أو تنهي الطلب باستجابة مناسبة.

يمكن للمعالج إعادة كائن `Response` مباشرة، أو إرجاع `Promise` ينتج عنه `Response`، وهو ما يتيح استخدام العمليات غير المتزامنة، مثل قراءة البيانات من قاعدة البيانات.

## معاملات المسار

تتيح لك معاملات المسار استخراج قيم من عنوان الطلب نفسه، بدلًا من كتابة مسار مستقل لكل قيمة.

على سبيل المثال، بدلًا من تسجيل مسارات منفصلة للمستخدمين `1` و`2` و`3`، يمكنك استخدام مسار واحد:

```ts
app.get("/users/:userId", (ctx) => {
  return json({ userId: ctx.params.userId });
});
```

عند استقبال طلب مثل `GET /users/42`، تكون قيمة `ctx.params.userId` هي النص `"42"`.

### معاملات متعددة

يمكنك وضع أكثر من معامل في المسار:

```ts
app.get("/users/:userId/posts/:postId", (ctx) => {
  return json({
    userId: ctx.params.userId,
    postId: ctx.params.postId,
  });
});
```

إذا كان الطلب هو:

```http
GET /users/42/posts/7
```

فستكون النتيجة:

```json
{
  "userId": "42",
  "postId": "7"
}
```

تُستخرج القيم بحسب مواضعها في المسار، ويستنتج TypeScript أسماء المعاملات وأنواعها عند تسجيل المسار باستخدام نص حرفي. وتكون قيم معاملات المسار نصوصًا حتى عندما تبدو أرقامًا.

### المعاملات الاختيارية

أضف `?` بعد اسم المعامل لجعله اختياريًا:

```ts
app.get("/articles/:slug?", (ctx) => {
  return json({
    slug: ctx.params.slug ?? null,
  });
});
```

يسمح هذا النمط بمطابقة المسار مع قيمة `slug` أو من دونها، وفقًا لقواعد التوجيه في Barq.

على سبيل المثال:

- `/articles/barq-routing` يتيح قيمة `slug` وهي `"barq-routing"`.
- `/articles` يتيح قيمة غائبة، ويحوّلها المثال إلى `null` باستخدام `?? null`.

يدعم Barq توسعة الأجزاء الاختيارية إلى بدائل عند تسجيل المسار، لكن عدد المعاملات الاختيارية في النمط الواحد محدود بثمانية. لذلك، تجنّب الإفراط في استخدام الأجزاء الاختيارية، واستخدم مسارات منفصلة عندما يكون ذلك أوضح.

### معاملات `wildcard`

استخدم `*name` لالتقاط بقية المسار في معامل واحد:

```ts
import { App, text } from "@barqel/barq";

const app = new App();

app.get("/files/*path", (ctx) => {
  return text(ctx.params.path);
});
```

يمكن لهذا المسار التقاط الجزء المتبقي بعد `/files/`، مثل `docs/guide.md` عند طلب:

```http
GET /files/docs/guide.md
```

يجب أن يأتي معامل `wildcard` في نهاية المسار، لأنه مخصص لالتقاط بقية المسار.

**تنبيه أمني:** لا تتعامل مع قيم المعاملات باعتبارها بيانات موثوقة لمجرد أن المسار طابق النمط. تحقّق من القيم وحوّلها إلى الأنواع المطلوبة قبل استخدامها. فعلى سبيل المثال، تحقّق من أن معرّف المستخدم عدد صحيح صالح، وتأكد من أن مسارات الملفات لا تسمح بالوصول إلى ملفات خارج المجلد المسموح به.

## معاملات الاستعلام

تأتي معاملات الاستعلام بعد علامة `?` في عنوان الطلب، وتُستخدم عادةً لتحديد خيارات القراءة، مثل البحث والترقيم والترتيب.

مثال على طلب:

```http
GET /products?category=books&page=2
```

يمكنك قراءة قيمة واحدة باستخدام `ctx.queryParam(name)`:

```ts
app.get("/products", (ctx) => {
  const category = ctx.queryParam("category");
  const page = ctx.queryParam("page");

  return json({ category, page });
});
```

استخدم `ctx.queryParamAll(name)` عندما يكون اسم المعامل مكررًا وتحتاج إلى جميع قيمه:

```ts
app.get("/search", (ctx) => {
  const tags = ctx.queryParamAll("tag");

  return json({ tags });
});
```

على سبيل المثال، يتيح الطلب التالي عدة قيم للمعامل نفسه:

```http
GET /search?tag=laravel&tag=bun&tag=typescript
```

أما إذا كنت تحتاج إلى واجهة JavaScript القياسية `URLSearchParams` للتعامل مع معاملات الاستعلام، فيمكنك استخدام `ctx.query`:

```ts
app.get("/products", (ctx) => {
  const page = ctx.query.get("page");
  const categories = ctx.query.getAll("category");

  return json({ page, categories });
});
```

**متى تستخدم كل طريقة؟**

- استخدم `queryParam()` عند الحاجة إلى قيمة واحدة.
- استخدم `queryParamAll()` عندما تريد جميع القيم المتكررة لمعامل محدد.
- استخدم `ctx.query` عندما تحتاج إلى إمكانات `URLSearchParams` القياسية.

تذكّر أن قيم الاستعلام نصوص أيضًا. إذا كانت `page` تمثل رقم صفحة، فتحقق من صحتها وحوّلها إلى عدد قبل استخدامها في الحسابات أو استعلامات قاعدة البيانات.

## مجموعات المسارات

تساعد مجموعات المسارات (`Route Groups`) على تنظيم المسارات التي تشترك في بادئة أو وسائط برمجية. وهي مفيدة خصوصًا عندما يكبر التطبيق ويحتوي على وحدات مثل المستخدمين والإدارة والمنتجات.

### إنشاء مجموعة

```ts
app.group("/api/v1", requireApiKey, (api) => {
  api.get("/users/:id", (ctx) => {
    return json({ id: ctx.params.id });
  });

  api.group("/admin", (admin) => {
    admin.get("/summary", () => json({ ok: true }));
  });
});
```

في هذا المثال، أُنشئت مجموعة ببادئة `/api/v1`، وأُضيفت إليها الوسيطة `requireApiKey`. ثم سُجّل مسار للمستخدمين ومجموعة داخلية للإدارة.

تكون المسارات النهائية:

- `/api/v1/users/:id`
- `/api/v1/admin/summary`

وتُدمج البادئات عند تداخل المجموعات، لذلك لا تحتاج إلى تكرار `/api/v1` في كل مسار.

### استخدام الوسائط مع المجموعات

يمكنك إرفاق وسائط بالمجموعة لتطبيق منطق مشترك على المسارات المسجلة داخلها، مثل التحقق من مفتاح API أو تنفيذ فحوصات الوصول.

```ts
app.group("/api/v1", requireApiKey, (api) => {
  api.get("/profile", getProfile);
  api.get("/settings", getSettings);
});
```

هنا تشترك المسارات في الوسيطة `requireApiKey`، بدلًا من إضافتها إلى كل مسار على حدة.

تأكّد من أن الوسيطة تنفذ التحقق المطلوب بالفعل؛ فتسجيلها في المجموعة لا يعني تلقائيًا أن التطبيق يطبق نوعًا معينًا من المصادقة أو الصلاحيات.

### ما الذي تدعمه المجموعة؟

وفقًا لواجهة Barq، تدعم المجموعة:

- تسجيل طرق HTTP، بما فيها `all()`.
- إنشاء مجموعات متداخلة باستخدام `group()`.
- تسجيل مسارات WebSocket باستخدام `ws()`.
- تسجيل الإضافات باستخدام `plugin()`.
- إضافة الوسائط باستخدام `use()`.

تضيف `use()` الوسائط إلى المسارات المسجلة في المجموعة. استخدمها عندما تريد تنظيم الوسائط بصورة منفصلة عن تعريف المسارات، مع مراعاة ترتيب التسجيل الفعلي في تطبيقك.

## الإضافات

تتيح الإضافات (`Plugins`) تنظيم الوظائف المشتركة وإعادة استخدامها بين التطبيق أو مجموعات المسارات.

يمكن تسجيل إضافة على التطبيق:

```ts
app.plugin(myPlugin, options);
```

أو على مجموعة:

```ts
app.group("/api/v1", (api) => {
  api.plugin(myPlugin, options);
});
```

في المثالين، تمثل `myPlugin` دالة إضافة تعرفها في مشروعك، وتمثل `options` الخيارات التي تمررها إليها.

الإضافات في Barq دوال عادية؛ فلا يقوم الإطار بتحميل وحدات الإضافة أو حل اعتمادياتها تلقائيًا. لذلك، استورد الإضافة وأنشئ اعتمادياتها بالطريقة التي تناسب تطبيقك، ثم مرّر الخيارات المطلوبة وفقًا لتوقيع واجهة الإضافة التي تستخدمها.

راجع صفحة الإضافات لمعرفة تفاصيل دورة تسجيلها والوظائف التي يمكنها إضافتها.

## عدم تطابق طريقة HTTP

قد يتطابق مسار الطلب مع مسار مسجل في التطبيق، لكن من دون وجود معالج للطريقة المطلوبة. يختلف هذا الوضع عن طلب مسار غير موجود تمامًا.

### خطأ `405 Method Not Allowed`

إذا وجد Barq المسار، لكنه لا يملك معالجًا للطريقة المطلوبة عليه، فإنه يعيد:

```http
405 Method Not Allowed
Allow: GET, HEAD
```

الترويسة `Allow` توضح الطرق المسموح بها للمسار. والطرق المعروضة في المثال توضيحية؛ إذ تعتمد القيم الفعلية على المسار المسجل.

على سبيل المثال، إذا كان `/health` مسجلًا باستخدام `GET` فقط، ثم أرسل العميل طلبًا باستخدام `POST`، فقد تكون الاستجابة `405` بدلًا من `404`.

### خطأ `404 Not Found`

إذا لم يعثر Barq على مسار مطابق للطلب، فإنه يعيد استجابة `404`. ويمكن تخصيص المعالج المسؤول عن هذه الحالة باستخدام `app.notFound()`.

من المهم التمييز بين الحالتين:

- `404`: لا يوجد مسار مطابق.
- `405`: يوجد مسار مطابق، لكن طريقة HTTP المطلوبة غير مسموح بها عليه.

يساعد هذا التمييز على إظهار أخطاء العميل بوضوح، كما يسهل تشخيص مشكلات التوجيه أثناء التطوير.

## أفضل الممارسات

- **اختر طريقة HTTP المناسبة:** استخدم `GET` للقراءة، و`POST` للإنشاء أو تنفيذ العمليات، و`PATCH` للتحديث الجزئي.
- **استخدم أسماء واضحة للمعاملات:** مثل `:userId` و`:postId` بدلًا من أسماء عامة يصعب فهمها.
- **تحقّق من المدخلات:** معاملات المسار والاستعلام نصوص تحتاج إلى التحقق والتحويل قبل استخدامها.
- **نظّم المسارات في مجموعات:** اجمع المسارات ذات البادئة المشتركة أو الوسائط المشتركة.
- **لا تفرط في الأجزاء الاختيارية:** اجعل تعريف المسارات سهل القراءة والصيانة.
- **افصل بين المسار غير الموجود والطريقة غير المدعومة:** استفد من `404` و`405` لتوضيح سبب رفض الطلب.
- **استخدم الإضافات عند وجود وظائف مشتركة:** لكن لا تفترض أن Barq سيحمّل اعتماديات الإضافة تلقائيًا.

بهذه الأدوات يمكنك بناء واجهات HTTP منظمة، تبدأ بمسارات بسيطة ثم تتوسع إلى مجموعات ووحدات أكبر، مع إبقاء تعريف المسارات واضحًا وسهل الصيانة.
